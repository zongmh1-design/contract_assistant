# 项目边界

## 1. 项目定位

本项目是面向企业合同审批场景的风险审查辅助系统。它读取待办审批及合同附件，形成有证据定位的风险意见，并把意见回写到审批评论区。

系统只提供审查建议，不批准、拒绝合同，也不替代法务审核人和审批人作最终决定。

第一版以“培训项目 + 求职项目”为定位，优先保证流程清楚、状态可追踪、异常可重试、代码容易讲解，不追求生产级高并发和复杂基础设施。

## 2. 系统负责什么

- 拉取待处理的合同审批单，并按审批实例的唯一业务标识去重。
- 获取审批详情、表单信息和附件元数据。
- 下载合同附件，保存文件路径、下载状态和校验信息。
- 将文档读取、文本获取、必要时 OCR、字段提取、条款提取分为明确步骤。
- 保存合同基本字段、主要条款、原文证据、位置和提取状态。
- 使用确定性规则为主、LLM 辅助为后的方式进行风险审查。
- 保存规则命中、证据、风险等级、建议、汇总结果和审批关注点。
- 生成审查评论并通过审批系统适配器回写。
- 对关键失败记录明确原因，将任务转为 `blocked`，支持人工重试。
- 记录任务状态变化、处理日志和评论回写日志。

## 3. 系统不负责什么

- 不自动批准、拒绝、撤回或终止审批。
- 不代替法务人员确认合同是否合法、有效或可签署。
- 不修改合同正文，不提供电子签章或合同履约管理。
- 不负责审批系统自身的账号、组织、权限和流程配置。
- 不承诺识别所有文件类型、扫描件质量和复杂版式。
- 不在第一版建设前端页面。
- 不在第一版建设微服务、消息队列、分布式事务、复杂领域驱动设计或多 Agent 系统。
- 不在本阶段创建数据库、初始化脚本或任何业务实现。

## 4. 第一版使用 Mock 的能力

| 能力 | 第一版方式 | 保留的替换边界 |
| --- | --- | --- |
| 待办审批拉取 | Mock Approval System 返回固定样例 | `ApprovalGateway.list_pending_contract_approvals` |
| 审批详情获取 | Mock 返回表单和附件元数据 | `ApprovalGateway.get_contract_approval` |
| 附件下载 | 从 `sample_data/` 复制/读取样例文件并返回校验信息 | `ApprovalGateway.download_contract_attachment` |
| 评论回写 | Mock 记录请求与模拟响应，不调用企业平台 | `ApprovalGateway.write_approval_comment` |
| 合同样本 | 使用脱敏的示例合同 | 后续替换为授权测试材料 |

业务服务只依赖 `ApprovalGateway` 约定，不依赖 Mock 的数据格式或文件位置。未来接入真实平台时，只替换适配器，不修改合同审查核心流程。

## 5. 本阶段明确禁止实现

- LLM 调用
- OCR
- PDF 解析
- 规则引擎
- 审批系统真实接口
- 评论真实回写
- 前端

## 6. 第一版验收边界

最终第一版需要演示：待办拉取与去重、附件取得、文档解析、规则审查、结果保存、评论回写，以及关键异常进入 `blocked` 后的人工重试。

上述内容是第一版最终边界，不代表本设计阶段已经实现。
